# 0003. 분산 테스트는 실제 클러스터 대신 결정론적 시뮬레이션으로 한다

상태: 확정 (2026-09-18)

## 맥락

Level 3에서 검증해야 할 것은 단 하나의 불변식입니다.

> 커밋된(High Watermark 이하) 메시지는 어떤 리더 교체 후에도 사라지지 않는다.

이 불변식이 깨지는 상황은 타이밍에 달려 있습니다. 리더가 append한 직후, 팔로워가 따라오기 전, ZooKeeper 세션이 만료되기 직전 같은 좁은 창에서만 발생합니다.

브로커 3대를 Docker로 띄우고 손으로 죽이는 방식으로는 이 창을 못 맞춥니다. 한 번 실험에 수 분이 걸리고, 재현이 안 되고, 실패해도 어떤 순서였는지 모릅니다.

## 결정

브로커, 네트워크, 시계, 디스크를 전부 인터페이스 뒤로 숨기고, 한 프로세스 안에서 클러스터 전체를 시뮬레이션합니다.

- **시계**: 가짜 시계. 시뮬레이터가 틱을 전진시킵니다. `Thread.sleep`은 코드에서 금지합니다
- **네트워크**: 메시지 큐. 시드 기반 난수로 지연, 유실, 재정렬, 분단을 주입합니다
- **디스크**: 쓰기를 가로채서 "N바이트 쓰다가 중단" 같은 부분 쓰기를 재현합니다
- **컨트롤러**: 합의를 구현하지 않고, 시뮬레이터가 외부에서 리더 변경을 주입합니다 (ADR 0002)

매 틱마다 전역 불변식을 검사합니다. 위반이 나오면 시드와 이벤트 순서를 그대로 리포트에 남깁니다.

## 결과

불변식 위반 시드를 초 단위로, 수천 번 반복해서 찾을 수 있습니다. 찾은 시드는 그대로 회귀 테스트가 됩니다. **실패를 재현 가능한 자산으로 바꾸는 것**이 이 결정의 핵심입니다.

대신 제약이 생깁니다.

- 프로덕션 코드가 시계와 I/O를 직접 부르면 안 됩니다. 처음부터 주입받도록 설계해야 합니다. 이건 부담이 아니라 좋은 설계 강제 장치로 봅니다
- 실제 fsync 동작, OS 페이지 캐시, 실제 TCP 동작과는 괴리가 있습니다. 시뮬레이션이 통과해도 실제 환경에서 안 깨진다는 보장은 없습니다
- 따라서 시뮬레이션이 대체하지 못하는 것(실제 디스크 성능, 실제 네트워크 지연 분포)은 Level 2 벤치마크에서 별도로 측정합니다

## 대안

**Docker Compose로 실제 브로커 여러 대를 띄우고 죽인다**
실제에 가깝습니다. 느리고 재현이 안 됩니다. 최종 확인용으로 한 번은 돌려볼 가치가 있지만 주 검증 수단으로는 부적합합니다.

**Jepsen을 쓴다**
분산 시스템 검증의 표준에 가깝고 선형화 가능성 검사까지 해줍니다. Clojure 학습 비용이 붙고, 이 프로젝트 규모에 비해 무겁습니다. Jepsen이 하는 일을 축소해서 직접 만드는 쪽이 학습에는 오히려 낫습니다.

**단위 테스트로 상태 전이만 검증한다**
빠르고 쉽습니다. 실제 유실은 여러 컴포넌트의 타이밍이 겹쳐서 나기 때문에, 컴포넌트를 따로 보는 테스트로는 절대 안 잡힙니다.
