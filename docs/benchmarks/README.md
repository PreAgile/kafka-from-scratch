# 측정 결과

숫자 없는 트레이드오프 이야기는 공허합니다. 여기에 측정값을 남깁니다.

## 측정 원칙

- 조건을 먼저 적습니다. 머신, 디스크 종류, JVM 버전, 메시지 크기, 동시성
- 처리량만 보지 않고 p50, p99, p999 지연을 같이 봅니다. 평균만 보면 fsync 스파이크가 안 보입니다
- 웜업 후 측정합니다. JIT 컴파일 전 수치는 의미가 없습니다
- 원시 데이터를 CSV로 남기고, 그래프는 거기서 생성합니다

## 측정할 항목

| 항목 | 비교 대상 | 보려는 것 |
|---|---|---|
| fsync 정책 | 매번 / N건마다 / T밀리초마다 / 안 함 | 내구성과 처리량의 교환 비율 |
| 배치 크기 | 1, 16, 64, 256 레코드 | 배치가 성능의 몇 할인지 |
| linger 시간 | 0, 1, 5, 20 밀리초 | 처리량과 지연의 곡선 |
| 인덱스 밀도 | 전건 / 4KB마다 / 64KB마다 | 인덱스 크기와 조회 스캔 거리 |
| 메시지 크기 | 100B, 1KB, 10KB, 100KB | 어디서 네트워크가 병목이 되는지 |
| acks 수준 | 0 / 1 / all | 복제 대기가 지연에 미치는 영향 |
